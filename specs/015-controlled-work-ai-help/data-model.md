# Data Model: 015 — Trabalho em Modo Controlado com Ajuda da IA

One migration, `<ts>_controlled_work_ai_help`. New Prisma models (pinned by
`domain-boundary.spec.ts`): `AttemptIntegrityEvent`, `WorkHelpRequest`. Changed: `ClassActivity`
(one column), enum `ActivityExecutionMode` (one value). New enums: `AttemptIntegrityEventType`,
`WorkHelpStatus`.

## Changed: `class_activities`

| Column | Type | Rules |
|---|---|---|
| `execution_mode` | `activity_execution_mode` (`NORMAL`, **`CONTROLLED`**) | CHECK `type = 'ASSIGNMENT' OR execution_mode = 'NORMAL'` |
| `ai_help_allowance` | `smallint NOT NULL DEFAULT 0` | CHECK `IN (0, 3)`; CHECK `type = 'ASSIGNMENT' OR ai_help_allowance = 0` |

Trigger (replaces the 012 rule for the mode): `execution_mode` and `ai_help_allowance` may change
only while `NOT EXISTS (SELECT 1 FROM activity_attempts WHERE activity_id = NEW.id)`; class, type,
grade and source stay immutable as before. Existing rows: `NORMAL`, 0.

## New: `attempt_integrity_events` (append-only)

| Column | Type | Rules |
|---|---|---|
| `id` | uuid PK | |
| `attempt_id`, `activity_id`, `student_user_id` | uuid | composite FK → `activity_attempts (id, activity_id, student_user_id)` |
| `client_event_id` | uuid NOT NULL | `UNIQUE (attempt_id, client_event_id)`; generated by the client, or by the server for its own `TYPING_LIMIT_EXCEEDED` |
| `type` | `attempt_integrity_event_type` | see below |
| `question_id` | uuid NULL | composite FK → `class_activity_questions (id, activity_id)`; only clipboard and typing types |
| `recorded_at` | timestamptz | server clock |
| `client_occurred_at` | timestamptz NULL | set iff `buffered` (CHECK) |
| `buffered` | boolean | sent from the offline buffer |

Enum `attempt_integrity_event_type`: `SCREEN_LEFT`, `SCREEN_RETURNED`, `FULLSCREEN_EXITED`,
`FULLSCREEN_ENTERED`, `PAGE_LEAVE_ATTEMPTED`, `CONNECTION_LOST`, `CONNECTION_RESTORED`,
`PASTE_BLOCKED`, `COPY_BLOCKED`, `CUT_BLOCKED`,
`DROP_BLOCKED`, `TYPING_LIMIT_EXCEEDED`, `FULLSCREEN_UNAVAILABLE`, `DETECTION_UNAVAILABLE`.

Triggers: no UPDATE or DELETE (append-only, bypassed only by `resetDb`); INSERT only when the
activity is `CONTROLLED` and the attempt `IN_PROGRESS` (the server's `TYPING_LIMIT_EXCEEDED` too).
Indexes: `(attempt_id, recorded_at)`, `(activity_id)`.

Derived, never stored (`attempt-integrity/timeline.ts`): exits and their durations
(`SCREEN_LEFT → SCREEN_RETURNED`, `FULLSCREEN_EXITED → FULLSCREEN_ENTERED`,
`CONNECTION_LOST → CONNECTION_RESTORED`; an unpaired exit
ends at the next event or the submission), time away, clipboard and typing counts.

## New: `work_help_requests`

| Column | Type | Rules |
|---|---|---|
| `id` | uuid PK | the AI resource `WORK_HELP_REQUEST` |
| `attempt_id`, `activity_id`, `student_user_id` | uuid | composite FK → `activity_attempts` |
| `question_id` | uuid | composite FK → `class_activity_questions (id, activity_id)` |
| `idempotency_key` | uuid | `UNIQUE (attempt_id, idempotency_key)` |
| `question` | text | 1–500 characters (CHECK), the student's text |
| `status` | `work_help_status` | `REQUESTED`, `DELIVERED`, `OUT_OF_SCOPE`, `BLOCKED`, `FAILED` |
| `ai_execution_id` | uuid NULL UNIQUE | FK → `ai_executions`; set at creation |
| `message` | text NULL | ≤ 2 000; set iff `DELIVERED` or `OUT_OF_SCOPE` (CHECK) |
| `example_code` | text NULL | ≤ 1 500; only `DELIVERED` (CHECK) |
| `reason_code` | text NULL | `BLOCKED`: `MC_ALTERNATIVE_REFERENCED` / `EXPECTED_ANSWER_OVERLAP` / `SOLUTION_OVERLAP`; `FAILED`: the execution's error code; null otherwise (CHECK) |
| `requested_at` | timestamptz | server clock |
| `resolved_at` | timestamptz NULL | set iff not `REQUESTED` (CHECK) |

Constraints: partial `UNIQUE (attempt_id) WHERE status = 'REQUESTED'` (one pending per attempt);
trigger: `REQUESTED` → any terminal status once, then immutable; deferred constraint trigger: at
most 3 `DELIVERED` per attempt, and the activity's `ai_help_allowance` must be 3 for any row.
Index `(attempt_id, requested_at)`.

Derived: `used` = count of `DELIVERED` in the attempt; `pending` = a `REQUESTED` row exists.

## Changed: `ai_proposals` (006, research F9)

`ai_proposals_decided_by_chk` is relaxed: a proposal settled by its domain's rule
(`proposal.settle: "ON_MATERIALIZE"`) is APPROVED or REJECTED with `decided_by_user_id` NULL (actor
SYSTEM, `settledBy: "DOMAIN_RULE"` in the audit), so the 006 view shows no human decision. A
PARTIALLY_APPROVED proposal still needs its decider; READY_FOR_REVIEW and EXPIRED never have one.

## State transitions

```text
class_activities.execution_mode / ai_help_allowance:  editable ──(first attempt)──▶ fixed
work_help_requests.status:  REQUESTED ─┬─▶ DELIVERED      (materialize, leak check passed; consumed)
                                       ├─▶ OUT_OF_SCOPE   (materialize, model refused; not consumed)
                                       ├─▶ BLOCKED        (materialize, leak check failed; not consumed)
                                       └─▶ FAILED         (execution ended without completing; reconciled on read)
```

## Evidence classes (constitution X)

FACT: integrity events, the student's question, timestamps. SUGGESTION: the guidance.
RULE_RESULT: leak check, consumption, counts, durations, typing allowance. HUMAN_DECISION: grades
and any interpretation of the events.
