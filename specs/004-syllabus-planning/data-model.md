# Data Model: 004 — Área do Professor: Disciplinas, Ementas, Calendário de Aulas e Tópicos

This extends the models of 001 and 003. It adds one Prisma migration (`curriculum_planning`) plus SQL
for partial indexes, `CHECK`s, deferred constraints, immutability triggers and the new permissions.
None of this feature's flows deletes rows, except class meetings that have no linked topic.

Models in the schema after this feature (pinned by `domain-boundary.spec.ts`, E22):
- From 001: `User`, `Role`, `Permission`, `RolePermission`, `UserRole`, `TeacherProfile`,
  `StudentProfile`, `Invitation`, `UserToken`, `AdminBootstrap`, `Session`, `AuditEvent`,
  `AccessRecord`, `RateLimitCounter`.
- From 003: `SchoolClass`, `ClassInvitation`, `ClassInvitationDelivery`, `Enrollment`.
- New in 004: **`Subject`**, **`StoredFile`**, **`SyllabusDocument`**, **`SyllabusRevision`**,
  **`SyllabusGroup`**, **`SyllabusItem`**, **`ClassMeeting`**, **`ClassPlan`**, **`Topic`**,
  **`TopicSyllabusItem`**.

| `extractorVersion` | int? | |
| `processedAt` | timestamptz? | |
| `uploadedById` | uuid FK → `users.id` | |
| `createdAt`, `updatedAt` | timestamptz | |

Indexes:
- Worker queue: `(processing_status, next_attempt_at)`, plus `lease_expires_at` for `PROCESSING` rows.
- Subject listing: `(subject_id, version DESC)`.

Transitions (`SyllabusProcessingStateMachine`):

| From | To | Cause |
|------|----|-------|
| `UPLOADED` | `PROCESSING` | the worker claims the row |
| `PROCESSING` | `PROCESSED` | extraction finished |
| `PROCESSING` | `UPLOADED` | transient failure with attempts left (backoff) |
| `PROCESSING` | `FAILED` | `UNREADABLE`, or attempts exhausted |
| `PROCESSING` (lease expired) | `PROCESSING` | claimed again |
| `FAILED` | `UPLOADED` | the teacher chooses "Tentar novamente"; attempts reset |

`PROCESSED` is final.

## SyllabusRevision (`syllabus_revisions`)

| Field | Type | Rules |
|-------|------|-------|
| `id` | uuid PK | |
| `documentId` | uuid FK → `syllabus_documents.id` (Restrict) | |
| `number` | int | 1, 2… per document; `UNIQUE (document_id, number)` |
| `status` | `SyllabusRevisionStatus` | `DRAFT` → `CONFIRMED` |
| `source` | `SyllabusRevisionSource` | `EXTRACTION` (from `extraction`), `MANUAL` (typed by the teacher), `REVISION` (copied from a confirmed revision) |
| `basedOnRevisionId` | uuid? FK → `syllabus_revisions.id` | required when `source = REVISION` |
| `title` | text? | up to 200 |
| `syllabusText` | text? | up to 10,000 |
| `competencyText` | text? | up to 10,000 |
| `confirmedAt`, `confirmedById` | timestamptz?, uuid? | both set together (`CHECK`) |
| `createdAt`, `updatedAt` | timestamptz | |

Constraints:
- At most one `DRAFT` per document: `UNIQUE (document_id) WHERE status = 'DRAFT'`.
- A trigger rejects `UPDATE` and `DELETE` when `status = 'CONFIRMED'`. The only exception is the
  `DRAFT → CONFIRMED` transition itself.

## SyllabusGroup (`syllabus_groups`) and SyllabusItem (`syllabus_items`)

| Model | Fields | Rules |
|-------|--------|-------|
| `SyllabusGroup` | `id`, `revisionId` FK (Restrict), `position` int, `title` text? (up to 300) | `UNIQUE (revision_id, position)` |
| `SyllabusItem` | `id`, `revisionId` FK, `groupId` FK (same revision; composite FK `(group_id, revision_id)`), `position` int, `text` text (1–1000), `originItemId` uuid? FK → `syllabus_items.id` | `UNIQUE (group_id, position)` |

- A revision holds at most 500 items. Confirming requires at least one.
- Triggers reject `INSERT`, `UPDATE` and `DELETE` on groups and items of a `CONFIRMED` revision.
- Saving a draft (`PUT`) deletes and recreates that draft's groups and items; an item sent with its
  current `id` keeps its `originItemId`. Draft items are never
  referenced.

## ClassMeeting (`class_meetings`)

| Field | Type | Rules |
|-------|------|-------|
| `id` | uuid PK | |
| `classId` | uuid FK → `classes.id` (Restrict) | |
| `meetingDate` | date | inside `[starts_on, ends_on]` of the class (checked by the service) |
| `status` | `ClassMeetingStatus` | defaults to `PLANNED` |
| `createdAt`, `updatedAt` | timestamptz | |

`UNIQUE (class_id, meeting_date)`. A class has at most 200 meetings.

Meetings have no stored number. The number is derived on read:
`row_number() OVER (PARTITION BY class_id ORDER BY meeting_date)` (E12).

## ClassPlan (`class_plans`)

| Field | Type | Rules |
|-------|------|-------|
| `id` | uuid PK | |
| `classId` | uuid FK → `classes.id` (Restrict) | `UNIQUE` |
| `syllabusRevisionId` | uuid FK → `syllabus_revisions.id` (Restrict) | a `CONFIRMED` revision of a document of the class's subject (service) |
| `status` | `ClassPlanStatus` | defaults to `DRAFT` |
| `revision` | int | optimistic concurrency counter (E13), starts at 1 |
| `statusChangedAt` | timestamptz? | |
| `createdAt`, `updatedAt` | timestamptz | |

The plan is created when the class first selects a confirmed syllabus revision. A class without a
plan has no topics.

Transitions (`ClassPlanStateMachine`):
- `DRAFT → READY` requires at least one non-archived topic and turns every `DRAFT` topic into
  `ACTIVE`.
- `READY → DRAFT`: reopen.
- `READY → ACTIVE`: start.
- `DRAFT | READY | ACTIVE → ARCHIVED`.

Repeating a transition that is already applied does nothing. Any other transition returns
`409 INVALID_STATE_TRANSITION`.

When the plan is `ARCHIVED`, or its class is `ARCHIVED`, every write to the plan, its topics or its
meetings returns `409 PLAN_ARCHIVED`.

## Topic (`topics`)

| Field | Type | Rules |
|-------|------|-------|
| `id` | uuid PK | |
| `planId` | uuid FK → `class_plans.id` (Restrict) | |
| `meetingId` | uuid? FK → `class_meetings.id` (**Restrict**) | a meeting of the same class; the database blocks deleting a meeting that has topics (SC-008) |
| `title` | text | 1–200 |
| `description` | text? | up to 5000, plain text |
| `position` | int | `UNIQUE (plan_id, position) DEFERRABLE INITIALLY DEFERRED` |
| `origin` | `TopicOrigin` | `MANUAL` in this feature |
| `status` | `TopicStatus` | |
| `statusBeforeArchive` | `TopicStatus`? | set when archived |
| `mergedIntoTopicId` | uuid? FK → `topics.id` | merge (E14); same plan |
| `splitFromTopicId` | uuid? FK → `topics.id` | split (E14); same plan |
| `archivedAt` | timestamptz? | set iff `status = 'ARCHIVED'` (`CHECK`) |
| `createdById`, `updatedById` | uuid FK → `users.id` | |
| `createdAt`, `updatedAt` | timestamptz | |

A plan holds at most 300 topics.

Indexes:
- `(plan_id, status, position)`.
- `(meeting_id)`.

Transitions (`TopicStateMachine`):
- `DRAFT → ACTIVE`: when the plan is confirmed.
- `DRAFT | ACTIVE → ARCHIVED`: archive, merge or "remove".
- `ARCHIVED → statusBeforeArchive`: restore, or `ACTIVE` if the plan is already `READY` or `ACTIVE`.

Topics created while the plan is `READY` or `ACTIVE` start as `ACTIVE`.

Topics are never deleted.

## TopicSyllabusItem (`topic_syllabus_items`)

| Field | Type | Rules |
|-------|------|-------|
| `topicId` | uuid FK → `topics.id` (Restrict) | |
| `itemId` | uuid FK → `syllabus_items.id` (Restrict) | an item of a confirmed revision |
| `createdAt` | timestamptz | |

The primary key is `(topic_id, item_id)`. Index: `(item_id)`.

When a link is created, the item must belong to the revision the plan uses (service check,
`422 SYLLABUS_ITEM_NOT_IN_PLAN`). After the plan switches revisions, links to items that could not be
remapped stay in place and are reported as `outsideRevision` (E16).

## Invariants checked by tests

| Invariant | Guaranteed by |
|-----------|---------------|
| Original file never changes | trigger on `stored_files`; SHA-256 checked on read (SC-004) |
| Extracted content preserved | `extraction` written once, only in the `PROCESSING → PROCESSED` transition |
| Confirmed revision immutable | triggers on `syllabus_revisions`, groups and items (SC-004) |
| Same file does not create a new version | `UNIQUE (subject_id, sha256)` (FR-011) |
| One meeting per date | `UNIQUE (class_id, meeting_date)` |
| No topic linked to a missing meeting | FK `ON DELETE RESTRICT` (SC-008) |
| One executor per document | `FOR UPDATE SKIP LOCKED` plus the lease (SC-009) |
| Concurrent plan writes | `revision` compared in a conditional `UPDATE` (E13) |
| Isolation | every query goes through the teacher's subject or class (E3) |
